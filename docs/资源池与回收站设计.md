# 资源池与回收站设计（RM 视角）

> 从源仓库 `资源存储与回收站方案.md` 重新整理，去除平台相关表述，作为 RM 开源版权威设计参考。

## 1. 资源池物理布局

```
downloads/
├── resources/<rid>/<body_key8>/<文件>     # 资源本体库（去重核心）
├── _collections/collections.json          # 合集（按身份分桶）
├── _articles/users/<hash>/               # 共享文章衍生物（弱关联）
└── .thumbnail_cache/                      # 本地封面（md5(URL)[:12]+ext）
```

- **rid（资源主键）**：`r` + `sha256(f"{vid}|{seq}")[:15]`。外部来源按 `vid|seq` 确定性派生。
- **body_key8（本体键前 8 位）**：`compute_body_key(vid, quality, selector, cookie_fp)[:8]`。
  **画质不去重 = 不同子目录**（同一视频不同清晰度各自存档）。
- **本地文件（上传 / 目录导入）rid**：推荐用**内容哈希**派生（去重强度最高，见拆分方案 §4）。

## 2. 三级入池路由（单集 / 批量两入口均接）

1. **Tier-1 池命中**：同 `rid` + `body_key8` 已存在 → 直接引用 + 自动收录进库，**零重下**（跨用户去重）。
2. **Tier-2 缓存命中**：从 `DL_CACHE` 复制 staging 再迁入池。
3. **Tier-3 真下载/迁入**：staging 迁入池，**先于缓存登记**（避免缓存与池不一致）。

## 3. 合集引用模型

`_collections/collections.json` 按身份分桶：`{owner: {"collections": [...]}}`。
- 去重键 `(vid, 序号, 标题)`，序号取文件名前缀 `NNN`。
- 媒体库条目持 `resource_id`；取流时校验该 sid 合集含此 rid（防越权，否则 404）。
- 删除池文件只移引用、不删物理。

## 4. 完整回收站（T88 · 治本档）

删 `resources/` 引用 → 全局 **rid 级**活跃计数（遍历所有 owner，排除 `__trash__`）→ 归零入 admin `__trash__`：
- 物理 `resources/<rid>/` **保留**，条目保留最后引用的真实文件 `rel_path` / `title` / `trashed_from` / `trashed_at`。
- admin 端点：`GET /api/trash`（列表）/ `POST /api/trash/purge {rid}`（rmtree + 吊销同 rid shares + 文章默认保留不删）/ `POST /api/trash/restore {rid, target_sid?}`（默认回写 `trashed_from`，admin 可改派）。
- 引用复活清回收站：`_add_to_collection` 三处 return 均接 `remove_trash_entry(rid)`（防活跃引用与回收站矛盾）。
- serve_file 越权修复：引用校验循环**跳过 `__trash__`**（删后仍能 serve = 越权）。
- 前端回收站视图（仅 admin，按 `system:true` / id 过滤）+ 删除确认分支（按 refcount 区分"仍有人引用 / 将归零入站"）。

### 4.1 restore 必须整条快照还原

`ensure_trash_entry(..., item=None)` 存 `entry["item_snapshot"] = dict(item)` 完整快照；
`delete_files` 命中条目时记 `matched_item`；`trash_restore` 优先按快照逐字还原（旧条目无快照退回最小字段）。
**原则：restore 类操作一律整条快照，不做"最小字段重建"——字段清单会演进，重建必漏。**

## 5. per-user 共享失效（§2.8）

令牌生死只看"发布者本人正常合集（排除 `__trash__`）是否还持有该 rid 活跃引用"，**与全局 refcount 是否归零、及资源是否停在 admin 回收站均无关**。

- 某用户删除自身引用后其已无该 rid 活跃引用 → 其签发的令牌 `revoked + locked`，**不可重置开启**（`share_reactivate` 直接 409 拒）。
- 重置闸门 = 该用户把资源恢复到自己正常合集（`trash_restore` 清 `locked`，仍须手动 reopen）。
- 令牌结构增 `locked` 字段（`create_share`）；新增 `_owner_has_active_ref` / `_lock_owner_shares` / `_unlock_owner_shares`；`delete_files` 按 owner 加锁；`_resolve_share` 拒绝 locked。
- 文章衍生物立场：系统仅做生成时字幕路径弱关联；purge 默认保留文章 `.md` 不无差别删。

## 6. ingest API 契约（生产者统一入口）

```
POST /api/ingest
Headers: X-User-Email / X-Session-Id（由网关注入，RM 采信，规则同现有）
Body: { user, rid, body_key8, staged_path, title, subtitle_path?, cover? }
RM 内部：校验 rid/body_key8 → 池命中则引用+1 零重下，否则迁入池 → 登记合集引用
返回：{ ok, rid, resource_id, dedup_hit: bool }
```
下载器只 staging 到本地临时区、不直接挂资源池盘，耦合最低。rid 生成规则由 RM 提供。
