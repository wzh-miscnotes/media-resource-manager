# 变更说明（2026-11-24）

本次变更把 RM 从「视频资源池」扩展为同时管理视频与图文的双资源平台，并补齐图文的生产、编辑与管理闭环。此前图文只是视频字幕的衍生物（依附视频、无独立 `resource_id`、不进池）；现在它成为与视频平行的一类一等资源，拥有独立的身份、入池路径与读写闭环。两类资源只在实现层共用入池与回收基础设施，业务上彼此独立。

## 后端（app.py）

- **图文入池**：统一的 `_ingest_into_pool` 增加图文分支，新增 `source_type` / `url` / `published_at` / `content_type` 四个字段，视频条目零影响；合集去重键保持一致。
- **文章内联响应**：新增 `_file_response_or_inline`，`.html` 主文件以内联方式返回，供前端阅读器加载；不再带 `filename=` 触发附件下载。
- **图片资产 API**：新增 `/api/image/upload`、`/api/image/list`、`/api/image/{iid}`、`/api/image/trash`、`/api/image/restore`、`/api/image/purge`；图片按身份隔离存于 `users/<hash>/images/`，id 由内容哈希派生。
- **used 隔离修复**：`_article_used_image_ids` 只扫描当前用户自己合集下的文章正文，修复「A 引用图片导致 B 上传的同哈希图片无法清理」的越界问题。
- **富样式清洗**：服务端白名单补齐 `border-top` / `border-bottom` / `border-width` / `border-style`，保留原文的上下横线样式；仍拦截 `url()` / `javascript:` 与事件属性，输出确定性。

## 前端（index.html）

- **三 tab 分类**：全部 / 视频库 / 图文库，只做类型筛选，合集数据共用；网格渲染与卡片操作共用同一筛选列表，播放页 URL 带 `kind`，避免筛选后索引错位。
- **图文生产闭环**：新增「新建图文」与富文本编辑器（工具栏 + 图片插入），零 CDN、零外部依赖；保存前前端清洗、服务端白名单兜底。
- **图片库面板**：上传 / 插入 / used / 未使用 / 回收站 / 恢复 / 永久删除；「蓝色标题」按钮一键生成带上下横线与左竖条的 `h2`。
- **文章阅读器**：父页 fetch 正文、逐图转 data URI 后注入空 `sandbox` iframe，绕开 iframe 子资源不携带会话凭据导致的 401；支持全屏阅读，来源 URL 以安全链接形式显示。
- **编辑能力**：所有图文走同一编辑器；加载时读回正文与元数据、剥掉重复标题、图片转 data URI；保存时复用 `rid` 覆盖当前版本、旧版进回收站，共享图文只读。相对路径图片在保存前归一为 `/api/image/<id>`。
- **删除文案**：批量删除确认框按 `.html` 扩展名统计文章数，动态显示「N 个视频、M 篇图文」，不再一律写「视频」。

## 文档与配置

- 新增 `docs/图文一等资源演进.md`：架构系列续篇，讲述图文作为一等资源的演进、与视频的差异、富样式清洗、阅读器鉴权故障、图片资产与编辑闭环；全程脱敏，用中性代称。
- 新增 `docs/图文双资源架构图.svg` / `.png`：视频与图文双入口汇入统一入池、共用底层设施、展示层分叉的整体架构图。
- `.gitignore`：放行架构图 PNG（文章引用需随仓库发布）；新增两版公众号 HTML 的排除规则。

## 已知边界

- 图文来源采集为独立外部流程，不属于本系统功能；图文由系统内编辑器创建，或按约定格式经目录导入。
- 两版公众号 HTML 为本地发布产物，按仓库惯例不入库（图片为占位卡，需手动贴图）。
