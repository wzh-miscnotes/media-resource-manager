# 字幕 OCR 方案（RM 保留能力）

> 从源仓库 `OCR字幕识别方案说明.md` 重新整理。硬字幕 OCR 是媒体库的**手动动作**，与获取/下载解耦。

## 1. 定位

- 硬字幕 OCR 由用户在媒体库手动触发，**不随下载自动跑**。
- 引擎链路：ffmpeg 抽帧 → 烧帧号 → 拼图 → olmOCR 顺序识别 → 行序映射 → 落 `srt` / `txt`，与官方字幕共用命名。

## 2. 处理流程

1. `ffmpeg` 裁剪视频底部 28%（`crop` 滤镜，仅保留硬字幕带）。
2. `drawtext` 在每帧烧入**帧号**（便于后续行序还原）。
3. `tile=1x6` 竖向拼 6 帧为一张大图（减少模型调用次数、保留上下文）。
4. 调用 olmOCR 顺序识别（**workers=1 顺序**，LM Studio 并发负优化）。
5. 行序映射为主，缺格单帧兜底 → 生成 `_字幕.srt` / `_字幕.txt`。

## 3. 参数

- `fps` 档位：`0.5` / `1` / `2`（抽帧密度）。
- 覆盖前对旧字幕做 `.bak` 备份，防误覆盖。

## 4. 模型

- 统一 `allenai/olmocr-2-7b`（须由本地 LM Studio 加载）。
- LM Studio 并发负优化 → 顺序 1 路调用。

## 5. 前端

- 官方字幕存在的条目**隐藏 OCR 按钮**；其余条目显示 OCR 入口。
- 字幕来源标记 `subtitle_source`（official / ocr / 空）落 collections.json，前端 subTag 绿/紫/未知区分。
- OCR 模型/推理端点由 RM 配置（`config.py` 的 `llm_*`）指向本地推理服务。
